# 视觉方向

2026-11-20 定。读代码推不出来的选择和理由记在这里；色值、字号的具体数以 `src/styles/tokens.css` 为准。

## 一句话

水是软的，闸是硬的。会动、带渐变和弧线的只有水和闸室；字、标尺、按钮一律规矩、精确。

## 从哪来

产品名就是船闸。船闸这个东西自己带着一套图形：一级一级的闸室、闸门之间的缝、水位、闸墙上刻着数字的水尺。图标「梯级」已经用了前两样（三片、两道缝）。官网把它接着画下去，不另找比喻。

- **闸室**：竖着的长片，上下两端是圆弧，就是图标那三片的画法。过闸一节把三片接成八片，一片比一片高。
- **闸缝**：片与片之间 14 个单位宽的缝（图标的尺寸）。它是全页唯一的分隔图形：节与节之间、按钮里的细节、闯闸演示里关上的那道门。
- **水**：渐变从上到下。首屏背景是一段着色器画的「从水下往上看」（见下面「首屏」）；过闸是一段写实的影片（见下面）。
- **水尺**：过闸的平面图（后备的那一版）左边的一根刻度尺，标着八级，浮标跟着船停在当前这一级。手机上只留刻度，不显示数字。

## 首屏

### 水下仰望（2026-11-22）

用户要首屏有「清澈感」。原来的背景是深海里斜照下来的几道光，加上一整块实心的深色终端，又深又闷。用户先想到「一条鱼在深海光晕的海里游」，看过三个方向后选了「水下仰望」：

- 站在一池清水的底下往上看：上半屏是水面的底面，按透视铺开的波一格一格地晃，越远越密，糊进雾里；顶上偏右一扇亮窗透进天光（窗里是青的，不发白），光柱从那里往下照，跟着水面晃。
- 水里飘着三层远近的细微尘，被光柱照到的地方亮：这是让人一眼觉得「水是清的」的关键。
- 终端是一块深色的磨砂玻璃：着色器在它后面画糊开、压暗的水（放大三倍的同一片波光），终端的底半透明。不用 `backdrop-filter`（后面的水每帧都在动，太费）。
- 字压在亮水面上：标题和副标题身后一圈柔和的暗晕，副标题用正文的白；标题那一块水面也稍微压暗一点。
- 选它而不选鱼：鱼跟「十个角色按顺序把需求做完」没有关系，首屏会说不清产品；从水下往上看保留了全页「从深水里被闸一级级托上来、最后到天亮」那条线。

### 终端


2026-11-22 定。首屏原来是标题加图标那三片；现在右边是一个终端，里面一个 Claude Code 会话跑完一趟：这个产品的界面就是终端里的一段会话，拿它当首屏比任何比喻都直接。

- 讲的是一件事：你说一句需求 → 项目经理亮出需求稿、你批准 → 八段一段段往前走 → 实现时有个角色想写不归它管的文件，被门禁拦下，改由认领它的角色写 → 业务验收「结论：通过」。真文字只放在这条线上，命令和文件名是等宽字。
- 没有光标，是键盘在动；回车用一个小键帽表示。内容贴着底部往上长，和真的终端一样；两条需求轮流跑，跑完以后看不见地复位，接上下一圈。
- 颜色：门禁是白底反白（全屏最重的一处），水光那个青只给「结论：通过」、正在跑的那一格和需求稿里选中的那项。没有红色：拦下靠反白和原话，不靠警示色。
- 终端压在水面上，不垫板子。水面活着时它是一块深色的磨砂玻璃（见上面「水下仰望」）；水落到静态时是实心的面，也不是一整块平的暗色：左上亮一点、往右下沉下去，顶边一道细高光。终端是一扇完整的窗口，左右对齐页面内容区的边线（和页头的标志、右边的按钮一条线），不出画：试过从屏幕右边出画，在这个页面上和页头对不齐、一头被屏幕切掉，看着失衡，用户否掉了。
- 终端里的动也守「水慢、闸快」：整段记录往上推是水位在升（0.7 秒、水的曲线），只有门禁那块牌子像闸门一样快快落定；段与段之间留够看的时间，一圈二十四秒上下。原来一行 0.26 秒弹出来、每段半秒一换，和慢慢晃的水面撞在一起，用户看了说「不是很和谐，有点冲突」。
- 英文页的终端是英文的（译过的会话，下面一行小字说明插件本身是中文的）：原来两页都放中文，用户看英文页说「英文模式下，这边也需要改成英文的」（2026-11-23）。
- 首屏只留一个按钮「去 GitHub 点星」。原来旁边还有一个「看一趟怎么跑」跳到过闸，用户说「太 low 了，去掉」（2026-11-23）；往下滚就是过闸，不用按钮带。
- 电脑上一律左字右终端，终端 600 见方上下。很高的窗口里首屏不撑满一整屏（最高 1120），下一节从底下露出来，不让上下空着几百像素的水。中间试过窗口偏方又够高时改成上下排（终端整条铺开，1270×1150），用户看了说「PC 端可以做成一直左右布局」「窗口这一整块内容有点大」，2026-11-23 改回来。字最多放大到 1.45 倍，再多的地方让终端变宽、变高，不让字越来越大。

## 首屏和过闸之间

首屏底下是一小节「让 AI 直接写，常见的三件事」，再往下是过闸的标题和画面。这一段夹在两块很满的画面中间，原来是一整块平的深蓝：首屏底边一道接缝、三句话画成浅色胶囊（像三个按钮）、下面空一大截、影片横着一刀切进来，用户说「很突兀」。现在（2026-11-22）：

- 首屏的底色最下面收到下一节的底色，没有接缝。
- 三句话照首屏终端里会话记录的写法：圆点后面是它说的话，折角（└）后面是实际发生的事。
- 两节之间不重复留两份空。
- 过闸画面的上沿从这一节的底色里淡出来，开头远处的水是慢慢露出来的。

## 过闸怎么演

过闸是全页最花力气的一处，改过四版，都是做出来看过以后定的：

1. 平面的图：八个闸室排成一排，水一室一室注满。看过以后的结论：画面太单一，跟着滚动走的感觉不自然。
2. 浏览器里实时画的三维场景（three.js）：镜头跟着船走。看过以后的结论：都是几何体拼的，质感不够。
3. 离线渲染的写实影片（Blender 渲的八级石砌船闸、窄船、夜里到日出），滚到哪播到哪（2026-11-20 到 22）。用户的意见：「主要痛点是滚动卡顿，希望滚动停下画面还能动」——影片停下就定格；另外最后天亮那一下整个发白。
4. 现在这一版（2026-11-23）：**一条鱼游过八段景**。中间试过两版在网页里实时画的「上浮过闸」（镜头在闸室里往上浮），用户说「太单调，画面一直在重复，鱼太假」「每个场景都要大变样」，于是先和用户定了八段场景（主仓库 `docs/superpowers/specs/2026-11-22-过闸场景.md`），再做。

现在这一版怎么来的：

- 侧面看、平着游：鱼头朝右，在画面中间偏右；往下滚，镜头跟着往右走，世界从右往左流过去。远景、中景两层视差，远景慢。
- 八段八种地貌，一路从海里游进运河再浮出水面，对上「船闸连接两种水位」：珊瑚礁 → 海草床 → 海藻森林 → 岩石峡谷和鱼群 → 船闸闸室 → 水母群 → 清澈的河道 → 浅水和出水。交界处不硬切：前一段在交界带里变稀、后一段长出来，水色和能见度一路渐变。
- 景是 Blender 离线渲的长条图（`tools/reef/`）：珊瑚、海草、巨藻、芦苇是程序生成的，沙地、碎石、岩石、卵石、混凝土用 Poly Haven 的 CC0 扫描贴图，礁石用它的 CC0 模型。水是一层按距离吃掉红光、混进水色的雾，所以远处是蓝绿的、近处颜色是正的。
- 网页里实时叠：水面投下来晃动的光斑（只落在被阳光直射的面上）、海葵海扇海草随水摆、斜斜的光柱、漂浮的微粒、气泡、小鱼群（峡谷那一段是一大团，鱼游过时让开）、水母（渲好的序列帧，一张一缩）。滚动停下时这些照样在动，鱼悬着、胸鳍划水、腮一张一合，不定时窜一下、抬头低头；主线进度用软弹簧追滚动，停下有惯性。
- 鱼是渲好的序列帧（停着、游着各一圈），有单独的眼球和角膜、上下颌、能掀开的鳃盖和里面的鳃丝、由前往后变小的鳞片和侧线、带鳍条的透光鳍。

页面上：

- 过闸的标题下面不再解释「poundlock 这个名字就是船闸」：用户说「不必解释，太 low 了」（2026-11-23）。画面自己会演。
- 滚轮滚一下切一段：粘住的时候滚一格，页面滑到下一段场景的正中，画面带着惯性追过去；连着快滚也只走一段，第一段往上、最后一段往下照常滚出去。用户提的「能不能做成滚轮滚一下，就切换一下场景」（2026-11-23）。键盘、触屏照常连续地走。
- 画面铺满视口，左边压着当前这一段的说明，底下是一路落下来的产物，字的底下垫一层往画面里淡出去的暗色。水下一路都偏暗，所以字从头到尾用浅色。
- 说明的字跟着视口长（宽和高里取小的那个），大屏上标题到 72px、说明 26px：原来固定在 48px 和 21px，用户在 1878×1503 的屏上看说「文字部分可以稍微大一点」（2026-11-23）。标题上面一根八格的水尺，走到第几段亮第几格。换段时这一段的名字、说明、角色依次从下面浮上来、由糊变清（错开几十毫秒），旧的往上淡走；往回滚反过来。
- 最后一段出水：水线从画面顶上扫下来，水线以上是芦苇、睡莲叶、对岸和蓝天，停在「水上七成多、水下两成多」的一幅；字淡出去，页头换成浅色段的样子。往下一节的亮色只在最后一点点进度里从最底下升起一成半，不把画面洗白。
- 视口太矮、放不下一段说明加画面时（小手机、横过来的手机、把浏览器放大到 200% 的窗口），不开这个粘住的舞台，这一节是一张静态的清单。稍矮一点但还放得下的，省着用：画面矮一点，字小一号，产物清单只留一行。
- 平面的那张图留着，当后备：访客要求减少动效时是一张静态的图加清单；没有 WebGL、开了省流量、长条图下不来、设备画不动，用平面的图照常演八拍。

## 配色

「清水」：海军蓝、青、白。2026-11-20 从三套候选里挑的（原来那套是从图标取的青绿配暖白，做出来不好看，换掉了）。具体的值以 `src/styles/tokens.css` 为准，这里只记主要的几个。

| 名字 | 色值 | 用在哪 |
| --- | --- | --- |
| 深海 | `#041B33`、`#051F38` | 深色段的底 |
| 海水 | `#0B6088` | 首屏水面的亮端 |
| 水光 | `#7FE3FF` | 深色段的强调、光 |
| 浅水 | `#2CC7E0`、`#8EEBFA`、`#FFFFFF` | 图标三片的水 |
| 晴空 | `#F3F9FC`、`#E2EEF5` | 浅色段的底 |
| 墨 | `#0A2233` | 浅色段的字 |
| 蓝 | `#0A6A9B`、`#0B79B5`、`#1E4FC4` | 浅色段的强调 |

过闸画面里的暖色（珊瑚的粉、橙、黄，阳光）是画面里的颜色，不进页面的调色板：页面的界面元素不出现任何橙、红、棕，不用衬线。

品牌文件（`design/logo/` 里的图标、分享预览图）还是原来的青绿色，没有跟着改：那是定了稿的品牌资产，改不改由用户定。

## 字

一个家族，中英同一套：IBM Plex（OFL）。

- 正文和标题：IBM Plex Sans；中文用 IBM Plex Sans SC。中文字体按文案里实际用到的字裁成子集，自托管。
- 水尺和阶段编号的数字：IBM Plex Sans Condensed。闸墙上的水尺就是又高又窄的数字。
- 命令和文件名：IBM Plex Mono。只用在真的是代码的地方，不拿等宽字当装饰标签。

为什么是它：Plex 是为「人和机器」画的，笔画理性、细节硬朗，和软的水形成对照；它有简体中文版，中英两页的气质能一致；等宽和窄体是同一家族，不用再配。没选 Inter、Geist、Space Grotesk 这些，是因为它们是开发工具官网的默认选择。

设计文档原来写的是「中文用系统字体」。改成自托管子集的理由：Windows 上的系统中文字体（微软雅黑）在大字号下显得旧，而用户自己就在 Windows 上看。代价是多两百 KB 左右的字体；加载不出来时回落到系统字体。文案改了以后要重新裁子集，见仓库 `CLAUDE.md`。

字号按经典的排版阶梯走：14、16、18、21、24、36、48、60、72。标题不用全大写，不加字距。

## 版式

- 左对齐，靠着水尺这根脊。不做居中的大标题。
- 正文一行不超过 40 个汉字或 75 个西文字符。
- 不把内容切成一模一样的圆角卡片。闯闸是一块嵌进浅色段的深色面板；团队是一棵树；边界和安装是普通的列表和代码块。
- 面板和清单铺满内容区，右边都落在同一条线上（和页头右边的按钮一条线）：闯闸的面板、安装的面板和下面那张表、边界的清单。原来安装限 900、边界限 1040，在宽屏上比闯闸那块短一截，右边空着（2026-11-23）。
- 标题说法正式、直白：闯闸叫「六道门禁」，导语只说「六种常见的越界做法，每一种都由一道门禁在代码里拦下」。原来是「想偷懒？试试看」，用户说「写得很 low，要不要还是官方一点」（2026-11-23）。
- 会切换内容的地方高度不跟着跳：闯闸右边的说明框按六句里最长那句定高，点哪一项整块都不动；没点之前框里一句往哪儿点，不是一道空竖线。
- 「常见的三件事」宽屏上那三句原话用 24px，不像脚注；下面的「实际上」仍是小一号的灰字。
- 圆角只有三档：小（6）用在代码块和小控件，中（14，就是闸缝的宽度）用在面板，胶囊用在按钮。闸室两端的弧是真的圆弧，不是圆角。

## 动效

水慢，闸快。

- 水位升降：600 到 1200 毫秒，先快后慢地停住，没有回弹。
- 闸门关上：280 到 360 毫秒，带一点过冲，要有分量。
- 一直在动的只有首屏：水面（慢）和终端里那段会话（循环放，系统要求减少动效时停在跑完的那一帧）。没有呼吸灯，没有悬停时到处都动的卡片。
- 不给每一节加「淡入上滑」的入场。有编排的动效只花在三处：首屏的终端、过闸、闯闸里访客自己点的那一下。

## 不要的

和设计文档的红线一致：紫色渐变、渐变字、玻璃光球、emoji 当图标、「New」徽章、全大写加宽字距的小标签、呼吸灯、近黑底加荧光色的扁平硬边。另外不用：用中点连起来的元信息串、链接文字后面加箭头、每个标题上面再加一行小标签。
